# 启思学堂教学质量研究与目标架构

## 1. 研究问题

本报告回答四个问题：

1. AI 教师怎样组织一节课，才能形成理解而不是连续答题？
2. 编程学习中的什么行为可以作为掌握证据？
3. 系统如何决定讲解、提示、纠错、推进和复习？
4. 如何用可重复的指标判断教学质量是否改善？

研究结论不把“换一个更大的模型”视为主要方案。当前模型的知识覆盖足够承担 Java 基础讲解；主要瓶颈是知识表示、课程控制、证据归因和停止规则。

## 2. 证据基础

### 2.1 显性教学与 worked examples

新手缺少可以自行组织问题的知识结构。有效的初始教学需要：

- 激活必要旧知，但不把旧知检查扩展成漫长考试。
- 明确陈述本节可观察目标。
- 把复杂过程分成有意义的子目标。
- 先完整示范，再逐步撤除支架。
- 每次只增加一个新的变化来源。

相关依据：Rosenshine 的 Principles of Instruction，以及 worked-example effect 与 subgoal-labeled worked examples 研究。

### 2.2 KLI：围绕稳定知识成分组织教学

KLI（Knowledge-Learning-Instruction）框架区分：

- Knowledge components：学生最终要获得的稳定知识成分。
- Learning processes：获得或强化该知识成分的认知活动。
- Instructional events：触发这些活动的教学事件。

对本产品最重要的含义是：题目标题、变量名和上下文不是知识点。多个表面不同但依赖同一规则的任务，必须归并到同一个规范知识成分。

### 2.3 ICAP：学生参与不等于学生在学习

ICAP 将认知参与区分为：

- Passive：阅读或听讲。
- Active：点击、选择、抄写、运行现成代码。
- Constructive：生成预测、解释差异、补全推理、修改程序。
- Interactive：围绕双方产生的推理进行有实质内容的对话。

产品不能用“学生点击了运行”或“学生回复了 A”直接替代掌握证据。编程课堂应把活动推进到预测、追踪、修改和独立创建。

### 2.4 Retrieval practice 与延迟保持

即时重复学习容易提高熟悉感和信心，但延迟检索更能预测长期保持。即时正确只能证明当前可用，不能单独证明以后仍能提取。

延迟保持不应阻塞当前课程。学生完成独立迁移后可以继续，系统在后续课程中安排短检索确认 retained 状态。

### 2.5 编程教育：PRIMM、Parsons 与子目标示范

编程新手适合使用分层活动：

- Predict：先预测程序行为。
- Run：获得真实执行结果。
- Investigate：追踪变量、引用或控制流。
- Modify：只改变一个条件并解释影响。
- Make：独立构造一个满足目标的新程序。

当完整编写带来过高的非必要负荷时，可先使用无干扰项的 Parsons problem 或局部补全。随着能力提高，再转向独立编写。

## 3. 当前真实课堂审计

审计对象：真实 Java 后端开发课程 `sub_1784310392629` 的已保存聊天、教学会话和知识点。

### 3.1 回合分布

- 教师回合：56。
- 带学生任务的回合：40，约 71%。
- question/diagnose：14。
- feedback：26。
- explain/model：3。
- summary：2。

这与用户感受到的“全是作答”一致。系统已经能提供具体反馈，但讲解、示范和学生任务之间的比例仍失衡。

### 3.2 知识点碎片化

同一自增主题被保存为多个高度重叠的名称，例如：

- Java 表达式求值顺序与前置、后置自增运算。
- Java 表达式求值顺序与后置自增。
- Java 前置、后置自增的取值与变量更新。
- Java 前置自增的取值与变量更新。
- Java 后置自增的取值与变量更新。

当前课程有 10 个知识点，全部 mastery 低于 0.2，其中 4 个为 0。由于同一能力被拆成多个记录，教师会误判为仍有大量未验证内容，重复生成相近检查。

### 3.3 当前优点

- 已有讲解、练习、检查和总结的教案阶段。
- 已区分提示后完成与独立完成。
- 答错后能够直接讲解并公布答案。
- 已有独立判卷、教学复核和证据账本。
- Java 实验区已经能够提供真实 JVM 运行证据。

### 3.4 仍未解决的结构性问题

- `instructionDelivered` 更接近“发生过讲解动作”，不能证明讲解内容完整。
- 知识点名称由模型自由生成，缺少 canonical ID 和合并策略。
- 单一 mastery 数值混合了识别、提示完成、独立完成、迁移和延迟保持。
- 教师策略主要由提示词约束，客户端还没有完整的确定性教学决策表。
- 正确后的停止规则虽然有所限制，但历史会话仍显示连续解释性追问。
- 学习记忆记录策略成效的证据稀疏，无法可靠判断哪种讲法真正有效。
- 下一节重点主要来自模型总结，缺少前置知识图的硬约束。

## 4. 目标教学模型

### 4.1 稳定知识成分

每个 canonical knowledge component 应包含：

- `id`：稳定标识，不由每轮模型重新命名。
- `name`：学生可读名称。
- `prerequisites`：前置知识成分 ID。
- `mental_model`：需要建立的心智模型。
- `boundaries`：规则成立和不成立的边界。
- `worked_example_subgoals`：示例中的子目标。
- `contrasts`：关键正反例或易混对比。
- `misconceptions`：可观察的典型误解。
- `performance_objectives`：可作为证据的行为。
- `transfer_dimensions`：可以改变哪些条件来检查迁移。

`++i/i++` 不应保存为许多课程措辞，而应映射到少量稳定知识成分：

1. 表达式本次取得旧值还是新值。
2. 变量何时完成更新。
3. 多个子表达式的求值顺序。
4. 能否在新代码中追踪状态并迁移规则。

### 4.2 六级证据状态

掌握状态采用有序但不互相冒充的证据：

1. `introduced`：已经接受完整讲解。
2. `recognized`：能识别规则或正确例子。
3. `guided`：在提示或示范后完成。
4. `independent`：无提示完成同类任务。
5. `transferred`：条件变化后仍能完成。
6. `retained`：延迟后仍能独立提取。

规则：

- 自我报告“懂了”不更新上述状态。
- 运行成功本身不更新状态。
- guided 证据不能写成 independent。
- 达到 transferred 即可进入下一知识成分。
- retained 通过以后课程中的检索确认，不阻塞当前推进。

### 4.3 教学决策权归属

客户端拥有：

- 当前 canonical knowledge component。
- 当前证据状态和唯一缺口。
- 是否允许出题或要求提交。
- 是否必须直接纠错。
- 是否换表示方式或退回前置知识。
- 是否达到停止条件。
- 下一节允许选择的知识成分集合。

模型拥有：

- 在客户端给定边界内生成讲解、例子、类比和反馈。
- 根据真实作答提出候选错因。
- 生成满足指定 transfer dimension 的任务候选。

独立验证器拥有：

- 核对学科事实、参考答案和学生提交。
- 判断候选证据是否满足指定表现标准。

模型不得单独决定掌握、跳步、重复复查或下一课程主题。

## 5. 标准课时协议

### 5.1 定位

- 只检查本节必要的一个前置条件。
- 已有近期可信证据时跳过检查。
- 明确本节结束时学生将能做什么。

### 5.2 完整讲解

本阶段不显示待答区。老师必须完成：

1. 连接必要旧知。
2. 建立心智模型。
3. 给一个带子目标标签的最小示例。
4. 给一个关键对比或边界。
5. 用两句以内归纳规则。

`instructionDelivered` 只有在上述内容通过结构化检查后才能成立。

### 5.3 引导实践

- 新手先预测或补全一处关键步骤。
- 使用最少提示让学生继续。
- 连续提示应逐步撤除，而不是越来越接近照抄答案。
- 编程概念优先使用 PRIMM 实验。

### 5.4 独立迁移

- 使用同一个知识成分，但只改变一个明确维度。
- 不要求同时解释多个概念。
- 正确后立即停止该知识成分的即时检查。
- 不把措辞变化当作迁移，必须有结构或条件变化。

### 5.5 反馈与纠错

正确反馈：

- 引用学生本次提交中的具体证据。
- 说明为什么成立。
- 提炼可迁移规则。
- 达到停止条件时推进，不追加同构题。

错误反馈：

- 先指出做对的部分。
- 定位第一处关键差异。
- 老师完整演示正确过程并给出答案。
- 不要求重做原题。
- 新检查放到后续独立任务，不在同一反馈中强迫完成。

### 5.6 总结与后续复习

- 只记录有真实证据的状态。
- 区分当前表现与延迟保持。
- 生成一个简短、具体的后续检索任务。
- 下一知识成分必须满足前置关系，并且与当前内容形成可解释连接。

## 6. 确定性停止与降级规则

- 独立迁移正确：立即推进。
- 提示后正确：最多安排一次无提示新检查。
- 第一次错误：直接纠正并讲解。
- 同类错误第二次：缩小到一个变化并更换表示方式。
- 同类错误第三次：暂停当前难度，检查最小前置知识。
- 学生明确要求前进：允许推进，将未稳定证据加入复习队列。
- 学生提出概念问题：暂停当前任务，先完成讲解，不催答。
- 学生表达疲劳或烦躁：减少当前负担，不把情绪当成能力证据。
- 延迟复习失败：降低 retained 状态，不抹除已经存在的历史独立证据。

## 7. 编程课堂协议

### 7.1 活动梯度

根据学生状态选择最低必要负荷：

1. 代码阅读与结果识别。
2. 无干扰项 Parsons 排序或局部补全。
3. Predict-Run-Investigate。
4. Modify 一个条件。
5. Make 一个最小程序。
6. 在新情境中独立迁移。

### 7.2 可接受证据

- 对运行前结果作出可核对预测。
- 正确追踪关键变量、引用或控制流。
- 根据运行差异修改程序并说明修改作用。
- 独立创建满足表现目标的程序。
- 编译错误定位到具体语法或类型规则。

仅运行教师模板、复制完整答案或在看到输出后复述结果，不能单独证明掌握。

## 8. 教学质量自动评测

### 8.1 回合级不变量

- 一轮只有一个教学动作。
- explain/model 阶段没有评分任务。
- feedback 阶段先处理当前证据。
- 错误反馈包含明确判断、原因、正确过程和答案。
- 正确后没有未经教案授权的新题。
- 任务只对应一个 canonical knowledge component 和一个表现目标。
- 任务参考答案经过独立求解或执行验证。

### 8.2 课时级指标

- 讲解完整率，而非只统计 explain 标签。
- 学生任务占比与连续任务最长链。
- 重复语义任务率。
- 知识成分名称归并率。
- 提示撤除是否成功。
- 从 guided 到 independent、transferred 的证据转化。
- 达到停止条件后的多余回合数。
- 学生概念追问被正确暂停任务的比例。
- 教师学科错误率和参考答案冲突率。
- 延迟保持率。

任务占比没有固定的万能百分比，但当前真实课程约 71% 的教师回合都附带任务，且明确讲解仅 3 回合，已构成明显失衡。

### 8.3 必须覆盖的回放场景

1. 零基础学生首次接触概念。
2. 学生正确但理由含一个误解。
3. 学生错误，老师必须直接纠正。
4. 学生使用提示后改对。
5. 学生说“懂了”但没有证据。
6. 学生要求跳过或进入下一节。
7. 学生在任务中提出概念问题。
8. 同类错误连续出现三次。
9. Java 编译错误与运行时输出不一致。
10. 隔天检索失败但历史迁移证据仍存在。

每个场景应同时验证：可见教师内容、待答任务、课程阶段、证据账本、下一动作和重启恢复状态。

## 9. 实施优先级

### P0：先修教学控制基础

1. 建立 canonical knowledge component schema。
2. 对已有重复知识点做保守归并和证据迁移。
3. 实现六级证据状态。
4. 把推进、停止和降级规则移到客户端状态机。

### P1：提升编程教学质量

1. 将 PRIMM 变成正式教案步骤，而不是可选附件。
2. 增加 subgoal-labeled worked example。
3. 增加 Parsons/局部补全到独立编写的支架梯度。
4. 将实验运行、修改和提交绑定到表现目标。

### P2：建立持续教学评测

1. 增加真实聊天回放测试集。
2. 增加重复任务、过度检查和停止延迟指标。
3. 对每次教师策略记录独立成功或困难结果。
4. 用延迟保持结果校准复习计划，而不是反向阻塞当天课程。

## 11. 结论

启思学堂不应继续把“更会聊天”当作“更会教学”。可靠的 AI 教师需要：稳定知识成分、受控教学策略、分级证据、明确停止规则、真实编程活动和可回放评测。

模型可以继续使用国产通用大模型。产品竞争力来自模型外部的教学系统：它决定什么时候讲、讲到什么标准、学生做什么才算证据、何时必须停止追问，以及下一步为什么是当前学生真正需要的内容。
