## Context
启思学堂运行在 Windows Tauri WebView2 中。应用已有在线聊天模型配置，但教师语音只需要把已完成的教师回复读出来，不应再次请求模型，也不应把朗读状态写入课堂历史。

## Goals / Non-Goals
- Goals: 低延迟、本地可用、状态明确、键盘可操作，并严格区分新回复与历史消息。
- Non-Goals: 语音输入、声音克隆、在线音频生成、逐字高亮或音频文件持久化。

## Decisions
- Decision: 使用 Web Speech API 的 `speechSynthesis`，优先选择本地中文语音。
- Decision: 默认模式为“点击朗读”；自动朗读必须由用户在设置中主动开启。
- Decision: 将 Markdown 清洗、分句、语音选择和播放状态机放在独立模块中，并通过可注入适配器进行 Node 单元测试。
- Decision: 教师回复完整解析并渲染后才允许朗读；代码块转换为简短的屏幕查看提示，避免逐字符朗读代码。
- Alternatives considered: 调用配置中的 TTS 模型会增加网络延迟、费用和密钥暴露面，也无法保证现有模型网关支持音频，因此本次不采用。

## Risks / Trade-offs
- Windows 安装的中文语音可能因系统版本而不同 -> 按语言和本地语音能力评分选择，并保留系统默认回退。
- 较长回复可能被浏览器中断 -> 按中文标点分段并顺序播放。
- 自动朗读可能干扰其他任务 -> 仅朗读当前可见课堂的新回复，切换标签或隐藏窗口立即停止。

## Migration Plan
无需数据库迁移。语音模式和语速写入现有 `localStorage`；旧用户首次使用时默认为点击朗读。
