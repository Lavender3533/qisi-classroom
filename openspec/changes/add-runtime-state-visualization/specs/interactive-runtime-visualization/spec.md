## ADDED Requirements

### Requirement: 可信运行时状态模型
系统 SHALL 使用受限结构描述代码执行步骤、局部变量槽、表达式取值以及可选栈帧和堆引用，并 MUST NOT 将 Java 局部变量描述为稳定的物理内存地址。

#### Scenario: 展示前置与后置自增
- **WHEN** 教师针对受支持的 Java 自增表达式调用运行时状态图
- **THEN** 系统按真实求值顺序分别显示变量更新和表达式取值，并由确定性追踪结果给出最终变量与结果

#### Scenario: 语法不受支持
- **WHEN** 客户端不能确定性追踪代码且模型图示未通过独立复核
- **THEN** 系统不得展示推测的运行时状态，只能降级为静态概念或步骤说明

### Requirement: 可控制的逐步演示
系统 SHALL 允许学生前进、后退和重置运行时状态图，并 MUST 在每一步同时显示当前代码、变化对象、变化前后值和文本说明。

#### Scenario: 学生查看下一步
- **WHEN** 学生激活“下一步”
- **THEN** 系统只推进一个执行步骤，高亮本步发生变化的状态，并更新可读步骤计数

#### Scenario: 学生回看上一步
- **WHEN** 学生激活“上一步”或“重置”
- **THEN** 系统恢复对应历史快照，不重新请求模型且不改变课堂任务或掌握度

### Requirement: 教学触发与认知负荷
系统 SHALL 只在变量状态、求值顺序、引用关系或调用栈对当前卡点有直接帮助时展示运行时状态图，并 MUST 保留静态文本等价内容。

#### Scenario: 学生混淆变量值与表达式值
- **WHEN** 教师检测到学生对更新时机存在可观察的混淆
- **THEN** 教师可以插入运行时状态图，并保持当前待答任务不变

#### Scenario: 减少动态效果
- **WHEN** 系统检测到 `prefers-reduced-motion: reduce`
- **THEN** 状态仍可逐步切换，但取消位移和连续动画且所有信息保持可读
