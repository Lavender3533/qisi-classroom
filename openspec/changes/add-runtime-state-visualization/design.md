## Context
现有 `visual` 只支持静态步骤、对比和概念列表。应用已经能确定性追踪部分 Java 累加代码，也有独立教师内容复核，因此可以在不引入通用代码执行器的前提下先建立受限、可信的运行时状态演示。

## Goals / Non-Goals
- Goals: 让学生逐步观察变量状态和表达式取值；建立可扩展到栈帧与堆引用的统一结构；保证图示与真实执行语义一致。
- Non-Goals: 展示真实物理内存地址；实现完整 JVM；执行任意不受信任代码；制作装饰性动画。

## Decisions
- Decision: 使用 `runtime_state` 作为现有 `visual` 的新类型，步骤包含当前代码片段、说明、变量槽、表达式值以及可选栈/堆关系。
- Decision: 简单受支持表达式由客户端确定性追踪器产生步骤；模型不得覆盖追踪结果。
- Decision: 控件只有上一步、下一步、重置和步骤计数，状态变化使用短促高亮，不自动循环播放。
- Decision: Java 局部变量标注为“局部变量槽”，只有对象引用关系才进入“堆对象”区域，不显示虚构内存地址。
- Decision: 所有状态都有文本等价描述；开启 `prefers-reduced-motion` 时取消位移动画，只保留即时状态切换。

## Risks / Trade-offs
- 图示可能强化错误心智模型 -> 使用语言语义名称并让复杂图示通过独立复核。
- 通用执行模拟范围过大 -> 第一阶段只支持可确定性追踪的表达式，未支持语法降级为静态图。
- 动画分散注意力 -> 不自动播放，一次只高亮当前变化的一个区域。

## Migration Plan
新增类型保持向后兼容；旧 `steps`、`comparison` 和 `concept` 图示不变。无法识别的运行时图示回退为静态步骤列表。
