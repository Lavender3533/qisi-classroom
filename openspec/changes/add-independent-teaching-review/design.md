## Context
课堂流式响应当前在收到非 JSON 文本片段时立即写入 DOM。完整响应随后才经过 `parseAIResponse`、教师回合策略和质量评分。质量评分只记录 warning，不阻止错误内容；独立判卷也只约束学生答案后的正误反馈，不检查教师刚生成的新知识和新题。

## Goals / Non-Goals
- Goals: 在显示前独立复核高风险教学内容；发现明确学科错误时给出完整可验证替代回合；保护学生证据权威；提供准确等待状态；用真实错误讲解做对抗评测。
- Non-Goals: 不要求公开模型内部思维链；不把所有闲聊、课堂确认和总结都增加一次模型调用；不声称同一模型的隔离调用等于不同机构审核；不因复核服务故障阻塞整个课堂。

## Decisions
- Decision: 新增纯函数模块 `teacher-review.js`，负责判断是否需要复核、严格规范化结果和安全合并替代回合。
- Decision: 复核目标分为 `message`、`task_prompt`、`reference_answer`、`criteria`、`visual`。每个问题必须给出目标枚举、逐字片段、可核对理由和修正内容。
- Decision: `pass` 要求置信度至少 0.72 且没有问题；`revise` 要求置信度至少 0.75、至少一个有效问题和完整替代回合。
- Decision: 替代回合必须包含可见 message、合法 teacher_move、intent、checkpoint 和 student_task；知识检查/练习仍必须包含参考答案与评分要点。
- Decision: 合并替代回合时保留候选回合的 `student_state_update`、`learning_diagnosis`、`lesson_summary` 和 `homework_update`。这些字段随后仍受独立判卷和客户端证据策略约束。
- Decision: 候选流内容只累计，不在 DOM 中提前显示。主模型完成后进入 review 状态；通过或替换后才渲染最终内容。
- Decision: 复核不可用、字段无效或低置信度时返回 `unavailable`，继续现有客户端策略与质量记录，不伪称已复核。

## Risks / Trade-offs
- 高风险回合增加一次模型延迟和成本 -> 只复核包含讲解/示范/纠错或新评分任务的回合，并显示真实阶段。
- 复核器自身可能出错 -> 严格校验逐字问题证据；替代回合继续通过现有教师策略、单任务和独立判卷约束；真实对抗评测覆盖错误答案键与提示注入。
- 替代回合可能改变教学风格 -> 只允许在可信 revise 时替换内容字段，学生画像、学情和课堂状态仍由客户端控制。
- 复核服务失败时仍可能显示未复核内容 -> 保持课堂可用并记录状态；未来可按学科风险配置为严格阻断模式。

## Migration Plan
1. 新命令与前端模块向后兼容；旧会话无需迁移。
2. 复核日志只保存 verdict、置信度、问题类别和目标，不保存隐藏答案或替代内容。
3. 回滚时移除复核调用即可恢复原生成路径。

## Open Questions
- 无。当前采用可用性优先的保守降级，明确区分“已复核”和“复核不可用”。
