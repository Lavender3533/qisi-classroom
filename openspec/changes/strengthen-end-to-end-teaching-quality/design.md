## Context
模型擅长生成内容，但不能独自拥有课堂状态权威。摸底、待答任务、纠错阶段和掌握证据必须由客户端根据可验证作答推进；模型只负责在约束内生成合适的学科内容。

## Goals / Non-Goals
- Goals: 减少低信息量追问；确保每轮只保留一个学生动作；纠错后必须独立迁移验证；任何模型格式异常都不泄露内部字段；建立可重复的真实教学评测。
- Non-Goals: 增加学生语音、虚拟形象、营销页面或新的模型供应商绑定。

## Decisions
- Decision: 新增摸底回答分类器，识别零基础、自述有基础、可验证作答、含糊回答和学习目标；分类结果只决定允许跳转的最早阶段，不直接更新掌握度。
- Decision: 摸底状态保存已观察证据标签，阶段推进取客户端分类与模型 `stage_complete` 的保守交集；“有基础”可跳到代表性任务，但不能跳过真实作答。
- Decision: 教师可见消息与当前 `student_task` 对齐；存在未完成任务时，额外问题和冲突任务由客户端移除。
- Decision: 结构化解析先提取完整平衡 JSON 对象，再做有限的格式修复；无法验证为教师回合时显示安全提示，不显示原始协议。
- Decision: 真实模型评测读取现有本机模型配置，但不输出 API Key，并以离线单元测试作为必过门槛。

## Risks / Trade-offs
- 回答分类错误导致阶段跳得过快 -> 最多跳到代表性任务，仍需可验证作答才能进入迁移或小测。
- 解析修复过度接受错误内容 -> 只修复围栏、前后文本、尾随逗号和智能引号等有限形式，并校验必要字段。
- 客户端约束使教师措辞略机械 -> 约束学生动作与状态，不限制例子、解释方式和自然语言表达。

## Migration Plan
旧摸底会话缺少证据标签时，从现有 `chatHistory` 重新分类并保守恢复；旧课堂任务和纠错上下文继续沿用现有 schema。
