## Context
课堂中央同时存在消息流、当前任务和代码编辑器。新增工具不能形成第三个永久占位面板，也不能把临时操作伪装成学生消息。桌面工作台已有底部可调整编辑器的交互基础，可复用为课堂工具抽屉。

## Goals / Non-Goals
- Goals: 提供低摩擦的临时画图与计算；支持键盘和触控笔；保留任务上下文；由学生决定是否把工具产物用于作答。
- Non-Goals: 多人协同白板；无限画布；数学 CAS；运行程序代码；教师远程控制画板。

## Decisions
- Decision: 工具栏位于当前输入入口上方，只显示画板和计算器图标及工具提示，不使用带说明文字的大按钮。
- Decision: 两个工具共享底部抽屉和拖动手柄；切换工具保留各自草稿，关闭抽屉不清空内容。
- Decision: 画板采用 Canvas 位图显示和可撤销笔画模型，草稿按科目保存在现有会话中；窗口缩放时重放笔画，避免拉伸失真。
- Decision: 计算器使用受限表达式解析器；只开放明确支持的运算符与函数，禁止 `eval`、`Function` 和任意属性访问。
- Decision: “插入作答”是显式动作。计算器插入文本结果；画板插入本地快照制品引用，不自动发送聊天消息、不更新掌握度。
- Decision: 工具抽屉与代码任务抽屉互斥；打开代码任务时保存并收起课堂工具，避免两个可调整面板竞争高度。

## Risks / Trade-offs
- Canvas 草稿体积增长 -> 保存笔画数据并限制数量，快照只在学生插入时生成。
- 计算器被用于绕过学习 -> 教师可看到学生主动插入的计算过程，但工具使用本身不作为掌握证据。
- 小窗口空间竞争 -> 默认抽屉高度受限，可拖动且支持一键收起，900×600 时保证任务提交按钮可见。

## Migration Plan
工具状态使用教学会话中的可选字段；没有字段的旧会话按空画板、空历史初始化。删除字段不会影响课堂消息与任务。
