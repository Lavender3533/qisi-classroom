## Context
当前任务工作区已经把学生答案与 `pendingStudentTask.key` 绑定，并在正式提交时调用独立判卷器。缺口发生在提交之前：教师看不到学生已经写下的步骤。直接把每次输入发送给教师模型会造成高频调用、竞态和无依据的掌握更新，也会把编辑器重新退化为聊天。

## Goals / Non-Goals
- Goals: 在学生停笔时观察有意义的过程草稿；给出一次只推进一小步的编辑器内反馈；恢复未提交草稿；保证临时观察不污染正式学习证据。
- Non-Goals: 逐键流式上传、屏幕录制、手写识别、替代正式提交、自动改写学生答案、在选择题或专用代码/测验编辑器中重复观察。

## Decisions
- Decision: 观察仅适用于 `knowledge_check` 或 `practice`、存在合法 `assessment` 且回答模式为 `extended` 的当前任务。短答案、学习偏好、准备确认、诊断追问和专用编辑器继续在提交后处理。
- Decision: 界面默认显示并启用“老师看草稿”开关，学生可以随时暂停；偏好写入 `localStorage`。观察在停笔 6 秒后触发，同一 task key 最多两次，相邻请求至少间隔 30 秒，完全相同的草稿不重复核对。
- Decision: 复用 `verify_student_answer`，但只读取归一化后的临时结果。`correct` 只表示当前草稿能成立，`insufficient` 只要求继续补足；`incorrect` 只有在逐字第一错误定位与修正原则通过客户端校验时才显示具体纠错，否则保持安静等待正式提交。
- Decision: 观察请求携带快照 task key 和草稿指纹。返回时再次检查页面连接、开关、当前任务、草稿内容和请求代次；任何不一致均丢弃结果。
- Decision: 每个科目只保存一个 `{taskKey, content, updatedAt}` 草稿记录。恢复时必须精确匹配当前 task key 且未超过 7 天；任务变化不会显示旧内容。草稿不包含评分契约。
- Decision: 临时反馈是任务编辑器中的全宽状态条，不生成学生消息或教师气泡，也不自动朗读，避免在学生思考时抢占话轮。

## Risks / Trade-offs
- 临时判定可能把尚未完成的正确过程误认为信息不足 -> 只提示继续补足，不评价能力，也不形成学习证据。
- 学生可能通过反复试探获得答案 -> 每任务最多两次，只给当前步骤或第一处原则，不显示隐藏参考答案。
- 模型调用增加 -> 仅过程型任务、停笔触发、指纹去重和 30 秒冷却共同限制调用量；学生可暂停。
- 本地草稿包含未提交内容 -> 状态明确可见，只保留每科目一个任务草稿并在 7 天后失效，不写入远端聊天或长期记忆。

## Migration Plan
无需数据迁移。旧用户没有草稿记录时从空编辑器开始；删除新增本地键即可回滚，旧版本会忽略它们。
