## ADDED Requirements

### Requirement: 透明且可控的草稿观察
系统 SHALL 对需要过程作答且具有隐藏评分契约的当前任务提供可见、可暂停的草稿观察状态，并 MUST 不在不支持的任务上伪装正在观察。

#### Scenario: 过程型任务开始作答
- **WHEN** 当前任务为具有合法评分契约的过程型 `knowledge_check` 或 `practice`
- **THEN** 系统显示已启用的老师观察开关，并允许学生在不离开编辑器的情况下暂停或恢复

#### Scenario: 短答案或专用编辑器任务
- **WHEN** 当前任务只需短答案、缺少评分契约，或由测验/代码专用编辑器接管
- **THEN** 系统不得发起草稿观察请求，也不得显示正在观察的状态

### Requirement: 停笔触发与调用限频
系统 MUST 只在草稿发生实质变化并停笔后请求临时核对，并 MUST 对每个任务执行次数、冷却和重复内容限制。

#### Scenario: 学生持续编辑过程答案
- **WHEN** 学生在观察已启用的过程型任务中持续输入
- **THEN** 系统重置停笔计时，不得按每次按键调用模型

#### Scenario: 相同草稿或达到上限
- **WHEN** 当前草稿与上次已观察内容相同、距上次请求不足冷却时间或当前任务已经观察两次
- **THEN** 系统不得再次请求临时核对

### Requirement: 任务绑定的临时反馈
系统 MUST 将观察请求与 task key、草稿指纹和请求代次绑定，并 SHALL 只显示通过客户端证据校验的小步反馈。

#### Scenario: 草稿第一处错误可定位
- **WHEN** 独立核对以足够置信度确认错误，并能从草稿逐字定位第一处错误及一条修正原则
- **THEN** 系统在当前编辑器中保留已成立部分并只提示检查第一处错误，不得给出学生尚未写出的完整答案

#### Scenario: 草稿信息不足或当前可成立
- **WHEN** 独立核对认为草稿信息不足或当前内容可成立
- **THEN** 系统只提示继续补足或确认完整性，不把临时结果宣称为正式正确

#### Scenario: 请求期间草稿或任务变化
- **WHEN** 临时核对返回时 task key、草稿指纹、请求代次、观察开关或页面状态任一不再匹配
- **THEN** 系统丢弃结果，不在新任务或新草稿上显示旧反馈

### Requirement: 临时观察与正式证据隔离
系统 MUST 把草稿观察视为未提交的临时辅导，不得写入聊天记录、掌握度、错题、正式判卷结果或长期教师记忆。

#### Scenario: 临时核对完成
- **WHEN** 系统得到任意草稿核对结论
- **THEN** 系统可以更新编辑器内临时状态，但不得调用正式答案证据更新链路或保存师生消息

#### Scenario: 学生正式提交
- **WHEN** 学生点击提交当前任务
- **THEN** 系统仍以完整提交内容执行现有任务 key 校验、聊天保存、独立判卷和教师反馈，临时观察结论不得替代该流程

### Requirement: 当前任务草稿恢复
系统 SHALL 按科目保存唯一当前任务草稿，并 MUST 只在 task key 精确匹配且记录未过期时恢复。

#### Scenario: 刷新未完成课堂
- **WHEN** 学生刷新后回到相同科目和相同 task key，且草稿保存未超过 7 天
- **THEN** 系统恢复未提交内容但不自动提交、不自动判定，也不把草稿渲染为聊天消息

#### Scenario: 教师替换当前任务
- **WHEN** 教师产生新的 task key
- **THEN** 系统显示空的新任务编辑器，不把上一任务草稿带入新任务
