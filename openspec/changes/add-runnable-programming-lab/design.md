## Context
应用已有 CodeMirror、Python 练习运行命令、课程文件目录和任务证据链，但没有 Java 编译运行能力，也没有能与讲解并排使用的持续实验空间。现有代码任务编辑器面向“提交答案”，不适合在概念讲解期间反复修改和观察。

## Goals / Non-Goals
- Goals: 让学生在当前课堂内真实创建、编辑、编译和运行最小 Java 程序；让老师基于真实输出教学；保持实验与任务证据严格绑定。
- Non-Goals: 复刻完整 IntelliJ IDEA、Maven/Gradle 依赖管理、调试器、任意第三方库、云端沙箱、自动执行教师生成代码。

## Decisions
- Decision: 实验区是课堂编辑器组内的第二分栏，宽度可调整并持久化；低于可用宽度时转为底部停靠。右侧学习档案仍是独立检查器。
- Decision: 第一阶段仅支持单个公开类及少量同目录辅助类。文件名从公开类名确定，运行入口必须是 `public static void main(String[] args)`。
- Decision: Rust 在应用数据目录下为每次运行创建隔离临时目录，分别调用 `javac` 和 `java`，限制源码长度、文件数、总输出与执行时间，运行结束后清理编译产物。
- Decision: 禁止网络、进程创建、反射、原生库、系统退出和任意文件 API。该限制面向本地学习场景的误操作防护，不宣称能抵御恶意代码；只有学生显式点击“运行”才允许执行。
- Decision: 教师通过结构化 `coding_lab` 描述实验目标、初始文件、建议观察点与可选任务键。客户端验证和裁剪该描述，模型不能提供 shell 参数或控制运行命令。
- Decision: “运行”只生成观察记录；“提交实验”才把代码、输出和任务键交给独立验证器，并按既有证据门槛决定是否推进教案。

## Risks / Trade-offs
- 本地 JVM 不是强安全沙箱 -> 严格拒绝危险 API、限制进程资源且不执行远程/自动代码；未来若开放多人或不可信内容，必须改为容器或远程隔离执行。
- 小窗口三栏拥挤 -> 900×600 下实验区改为底部面板，并允许一键最大化或收起。
- 模板直接暴露结论 -> 模板只提供可运行骨架和观察点，关键表达式或预测结果由任务配置决定是否留空。

## Migration Plan
无需数据库迁移。旧教学会话没有实验状态时保持原课堂布局；JDK 不可用时隐藏运行能力并显示诊断，不影响聊天和普通作答。
