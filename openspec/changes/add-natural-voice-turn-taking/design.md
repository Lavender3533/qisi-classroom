## Context
启思学堂已经在最终教师消息上提供本地语音朗读，并区分手动、自动和关闭模式。当前缺口是默认值和话轮管理：新用户不会自然听到教师开口，学生开始输入时也没有统一的让出话轮行为。

## Goals / Non-Goals
- Goals: 让首次课堂中的教师自然开口；学生操作回答区时立即获得话轮；只朗读最终、可见、当前上下文中的教师内容；可靠尊重持久化偏好。
- Non-Goals: 语音输入、在线 TTS、声音克隆、唤醒词、逐字高亮、后台播放或朗读历史消息。

## Decisions
- Decision: 仅当存储中没有合法模式时默认 `auto`；`manual` 与 `off` 等既有合法值不迁移、不覆盖。
- Decision: 使用显式的学生话轮状态。聚焦、输入或选择回答控件时取得话轮并停止朗读；提交回答时清除该状态，使随后到达的教师回复可以自动朗读。
- Decision: 自动朗读继续由最终消息绑定点触发，并在排队和实际执行两个时刻检查可见性、DOM 连接、话轮和自动播放降级状态。
- Decision: `not-allowed` 类型的自动朗读错误只触发一次会话级降级；不改写用户的持久化模式，下一次启动仍可在新的 WebView 会话中重试。
- Decision: 继续保留每条教师消息的点击朗读按钮，作为系统不允许自动播放时的直接降级路径。
- Alternatives considered: 只在设置页提示用户开启自动朗读仍需要学生主动配置，无法满足“老师应该会自己说话”；在线 TTS 增加延迟、费用和隐私面，本次不采用。

## Risks / Trade-offs
- 自动开口可能打断正在思考的学生 -> 学生一触碰回答区就立即停止，且手动与关闭偏好始终优先。
- Web Speech API 的自动播放限制在不同 WebView 版本中表现不同 -> 识别拒绝错误、显示一次清晰提示并降级为点击朗读。
- 输入控件类型分散 -> 使用集中式委托监听覆盖聊天、摸底、测验和代码练习答题区，并以契约测试锁定选择器与提交路径。

## Migration Plan
无需数据库迁移。现有 `localStorage` 中的 `manual`、`off`、`auto` 均原样保留；只有缺失、损坏或无法读取的模式采用新的 `auto` 默认值。
