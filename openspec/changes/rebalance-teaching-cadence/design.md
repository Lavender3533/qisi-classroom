## Context
现有系统把“始终只有一个待答任务”误实现成“始终必须有一个待答任务”。任务保护保证了判卷一致性，却压过教案阶段和学生的概念追问。

## Goals / Non-Goals
- Goals: 让教案决定讲授与检查节奏；让学生能够连续听懂一个知识块；让概念追问真正改变当前课堂动作；减少无意义的连续同构题。
- Non-Goals: 取消练习、取消独立判卷、降低正式测验的答案保护、用自由聊天替代教案。

## Decisions
- Decision: `explain` / `model` 阶段默认 `student_task.kind = none`，只有该知识块讲授完成并到达教案检查点时才生成任务。
- Decision: 概念追问不是当前任务作答。系统把当前任务保存为可恢复任务但从作答区移除，教师先完整回答追问。
- Decision: 正确答案不自动触发同构题。客户端依据教案当前步骤决定推进到讲授、练习、检查或总结。
- Decision: 迁移验证集中在 `check` 阶段；一次独立正确证据最多通过一个门槛，但不会因此在每轮继续出题。
- Decision: UI 只在存在具体、可作答任务时显示底部作答区；讲授阶段使用完整阅读空间。

## Risks / Trade-offs
- 检查次数减少可能降低即时证据密度 -> 每个知识块保留一次练习和一次独立检查，并由教案明确安排。
- 暂停任务可能让学生忘记原题 -> 保存为 `suspendedStudentTask`，只在讲授完成且仍适合当前步骤时恢复。
- 模型可能提前出题 -> 客户端按教案阶段过滤不合时宜的 `student_task`。

## Migration Plan
加载现有会话时，若当前教案处于讲解阶段但仍挂有知识检查任务，将其迁移为暂停任务并清空作答区。聊天历史、教案进度和已有证据保持不变。
