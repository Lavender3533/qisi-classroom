## Context
应用同时承担教学和测评。当前纠错状态机把两者混用：即使在普通课堂中，错误答案也先进入局部修正和原题重答，直到学生答对才提供后续教学。这保证了证据纯度，却削弱了教师责任和学习效率。

## Goals / Non-Goals
- Goals: 老师在错误发生后完成讲解；学生不必猜到原题正确；独立证据来自讲解后的新题；保留测评模式的答案保护。
- Non-Goals: 取消独立判卷；把老师讲过的答案记为学生掌握；在摸底或正式评估中立即泄露答案。

## Decisions
- Decision: 日常课堂第一次可信判错后进入 `explained`，教师正文必须包含错误定位、正确过程、正确答案和一个关键对比。
- Decision: 客户端使用独立判卷的参考答案与纠错焦点约束教师可见反馈；若模型遗漏正确答案，客户端要求修订或使用可信判卷反馈补足。
- Decision: 原题在讲解完成后关闭，下一待答任务必须是新同构题，不得复用原答案或要求学生复述讲解。
- Decision: 新同构题标记为 `independent`，只有该题可信答对才允许更新掌握度和推进教案。
- Decision: 摸底、章节评估、测验编辑器保持现有分次提示与答案揭示规则，不套用课堂直接纠错。

## Risks / Trade-offs
- 过早公布答案降低主动思考 -> 只在学生已经完成一次真实提交后讲解，提交前仍提供分级提示。
- 模型讲错正确答案 -> 继续使用独立判卷和教师复核，冲突时以可信判卷为准。
- 讲解后立即换题增加负担 -> 新题只改变一个条件，预计一分钟内完成，并允许学生选择暂停。

## Migration Plan
恢复旧纠错会话时，若已经存在可信错误判定，则不再要求继续修原题；系统生成一次完整纠错讲解并转入新同构复查。未获得可信判定的旧任务保持原状，避免猜测答案。
