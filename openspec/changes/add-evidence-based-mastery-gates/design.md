## Context
课时计划已经包含 `success_criteria`、分步目标和文字证据要求，课堂会话也持久化 `lessonProgress`。但 `lessonProgress` 目前只有步骤索引、尝试次数和状态；任意一次正向学情更新都可能成为推进条件，课堂总结也主要依赖模型自行复述证据。

## Goals / Non-Goals
- Goals: 让步骤推进由可审计证据决定；区分提示依赖、独立应用和迁移；向学生透明显示还差什么证据；兼容既有会话。
- Non-Goals: 不用一次课内表现推断长期能力；不要求每个知识点都做高风险考试；不新增远端服务或数据库迁移；不把内部置信度和编排术语直接展示给学生。

## Decisions
- Decision: 在 `lessonProgress` 内增加版本化证据账本，而不是新增数据库实体。会话 JSON 已具备本地持久化、恢复和向后兼容能力，足以承载单节短课的小型证据集合。
- Decision: 证据角色由客户端按证据产生时的当前教案阶段确定，不接受模型自行扩大证据等级。`explain` 对应理解检查，`practice` 对应独立同构应用，`check` 对应独立变式迁移。
- Decision: 正向证据必须同时满足当前待答任务可用于掌握、任务知识点与学情更新相符、置信度达标且支持级别为独立。提示后成功进入账本但不通过门槛。
- Decision: 每条证据使用待答任务、来源、作答和次数生成稳定键，重复提交不能重复填充证据槽位。
- Decision: 教案步骤可声明 `criterion_ids`；旧教案由客户端按阶段保守映射，练习证明首项标准，迁移检查证明剩余标准。
- Decision: 右侧检查器使用紧凑列表和文字状态，不新增浮空卡片。状态同时使用 Lucide 风格图标、文字和颜色，符合现有桌面工作台设计系统。

## Risks / Trade-offs
- 更严格的门槛会让部分课堂比以前多一道检查。通过一分钟短题、一次一个动作和主动续讲控制负担。
- 旧会话没有分级证据。保留原步骤位置，但在界面标为“旧记录，证据分级不可追溯”，不得伪装成新账本中的独立掌握。
- 模型可能生成与当前步骤不匹配的任务。客户端不让不匹配证据推进，并在下一轮提示中明确仍待验证的任务类型。

## Migration Plan
1. 新课初始化 `gateVersion` 和空证据账本。
2. 读取旧会话时保留 `currentStep`，此前步骤仅作为历史进度展示，不回填虚构证据。
3. 从当前步骤开始执行新门槛；新产生的证据按新格式持久化。
4. 若需回滚，旧代码会忽略 `lessonProgress` 中新增字段，步骤索引和状态仍可读取。

## Open Questions
- 无。当前短课结构固定为讲解、练习、迁移检查和总结，足以提供确定的客户端门槛。
